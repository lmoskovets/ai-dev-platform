# Issue tracker: GitHub

Issues and specs live in lmoskovets/ai-dev-platform.
Use the gh CLI from this repository.

Before creating issues, verify the target with:
gh repo view --json nameWithOwner

Publish specs and tickets as GitHub issues.
Read issue bodies, labels, and comments before acting.
Use native GitHub sub-issues and blocking dependencies.
If unavailable, record parent and blocker links in issue bodies.

Before closing an issue, post a comment explaining the outcome.

## Pull requests as a triage surface

PRs as a request surface: no.
